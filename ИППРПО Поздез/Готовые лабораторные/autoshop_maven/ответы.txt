1. Теория Maven

1. Что такое Apache Maven?
Apache Maven — это инструмент для автоматизации сборки Java-проектов. Он управляет зависимостями, компилирует исходный код, запускает тесты и создаёт готовые артефакты, например JAR-файлы.

2. Зачем Maven нужен в промышленной разработке?
Maven стандартизирует сборку проекта, упрощает подключение библиотек и позволяет разным разработчикам собирать проект одинаковым способом. Также его можно использовать в автоматизированных системах сборки и тестирования CI/CD.

3. Для чего используется pom.xml?
pom.xml — главный конфигурационный файл Maven-проекта. В нём указываются идентификаторы проекта, версия, зависимости, плагины и настройки сборки.

4. Что такое groupId, artifactId и version?
groupId — идентификатор организации или пространства имён проекта, например by.ipprpo.
artifactId — название проекта или создаваемого артефакта, например autoshop.
version — версия проекта, например 1.0-SNAPSHOT.
Вместе эти параметры определяют координаты Maven-артефакта.

5. Что такое Maven dependency?
Dependency — это зависимость, то есть внешняя библиотека или модуль, необходимые проекту. Например, JUnit используется для написания и запуска автоматизированных тестов.

6. Откуда Maven получает зависимости?
Обычно Maven скачивает библиотеки из удалённых Maven-репозиториев, например Maven Central, и сохраняет их в локальном репозитории на компьютере. После загрузки библиотека может использоваться повторно без повторного скачивания, если она уже доступна локально.

2. Структура проекта

7. Для чего нужен src/main/java?
В этом каталоге располагается основной исходный код приложения: классы, интерфейсы и перечисления, необходимые для работы программы.

8. Для чего нужен src/test/java?
В этом каталоге располагаются исходные файлы автоматизированных тестов. Например, тесты JUnit, которые проверяют работу классов приложения.

9. Для чего используется каталог target?
target — каталог, в который Maven помещает результаты сборки: скомпилированные классы, скомпилированные тесты, отчёты о тестировании и собранные JAR-файлы.

10. Где должны находиться ресурсы приложения?
Ресурсы приложения размещаются в src/main/resources. Например, это могут быть файлы конфигурации, шаблоны и другие файлы, необходимые программе во время работы.
Ресурсы тестов, если они нужны только тестам, можно хранить в src/test/resources.

3. Сборка и тестирование

11. Что происходит при выполнении mvn compile?
Maven выполняет необходимые предыдущие фазы жизненного цикла и компилирует основной исходный код проекта. В результате Java-файлы .java преобразуются в файлы .class, которые обычно сохраняются в target/classes.

12. Что происходит при выполнении mvn test?
Maven компилирует основной код и тесты, а затем запускает автоматизированные тесты через настроенный тестовый фреймворк, например JUnit. Результаты можно увидеть в консоли и в отчётах внутри target/surefire-reports.

13. Что делает mvn package?
Maven выполняет предыдущие необходимые фазы жизненного цикла, включая компиляцию и тестирование, а затем упаковывает проект в артефакт. Для обычного Java-проекта это, как правило, JAR-файл в каталоге target.

14. Чем package отличается от install?
package создаёт готовый артефакт, например JAR-файл, в каталоге target.
install выполняет предыдущие фазы, включая упаковку, а затем дополнительно помещает созданный артефакт в локальный Maven-репозиторий. Это позволяет другим локальным Maven-проектам использовать его как зависимость.

15. Что произойдёт, если один из тестов завершится ошибкой?
Maven зафиксирует провал тестирования и обычно завершит сборку со статусом BUILD FAILURE. В консоли и отчётах будет информация о тесте, который завершился ошибкой. Нужно найти причину, исправить код или тест и запустить проверку повторно.

16. Зачем зависимости указываются в pom.xml?
Чтобы Maven мог автоматически определить, какие библиотеки нужны проекту, загрузить их при необходимости и использовать во время сборки. Это избавляет разработчика от необходимости вручную скачивать и подключать каждый JAR-файл.

17. Зачем указывать версию зависимости?
Версия определяет конкретную редакцию библиотеки. Явное указание версии делает сборку более предсказуемой и снижает риск того, что после обновления библиотеки поведение проекта изменится.

18. Что такое транзитивные зависимости?
Транзитивные зависимости — это библиотеки, которые нужны другим библиотекам, подключённым к проекту. Maven может автоматически разрешать и загружать такие зависимости, поэтому разработчику не всегда нужно перечислять их вручную.

19. Чем зависимость для production-кода может отличаться от зависимости для тестов?
Зависимость для production-кода нужна самому приложению во время компиляции или работы. Тестовая зависимость нужна для разработки и выполнения тестов и обычно не включается в обычный исполняемый код приложения.
Например, для JUnit можно использовать область действия test:
<scope>test</scope>
Это означает, что зависимость предназначена для тестирования.

20. Почему Maven удобнее ручного подключения JAR-файлов?
Maven автоматически управляет скачиванием библиотек, их версиями и транзитивными зависимостями. Достаточно описать зависимости в pom.xml, чтобы другой разработчик мог получить их при сборке проекта, не настраивая каждую библиотеку вручную.

4. Maven в командной разработке

21. Как Maven может использоваться внутри CI/CD?
Maven запускается в автоматизированном конвейере CI/CD для сборки проекта, запуска тестов и создания артефактов. Если сборка или тесты завершаются ошибкой, конвейер может остановить дальнейшее развёртывание приложения.

22. Что произойдёт, если другой разработчик клонирует ваш проект?
Он получит исходный код и файл pom.xml. При наличии установленного JDK и доступа к репозиториям Maven сможет загрузить необходимые зависимости, собрать проект и запустить тесты.

23. Какие действия ему достаточно выполнить, чтобы получить собранный проект?
Открыть проект, убедиться, что настроен JDK, и выполнить команду:
mvn clean package
Она очистит предыдущие результаты сборки, выполнит необходимые этапы компиляции и тестирования и создаст JAR-файл в каталоге target. Если Maven доступен через IntelliJ IDEA, можно запустить соответствующие фазы через Maven Tool Window.

24. Как Maven связан с Jenkins?
Jenkins — это сервер автоматизации CI/CD, который может запускать Maven-команды. Например, после отправки изменений в репозиторий Jenkins может выполнить mvn clean test и проверить, что проект собирается и тесты проходят.
