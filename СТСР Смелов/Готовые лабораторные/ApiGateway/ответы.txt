### 🌐 REST и RESTful

**1. Что такое REST?**
REST (Representational State Transfer) — это **архитектурный стиль** для построения распределённых систем, 
в первую очередь веб-приложений. Он описывает, как клиент и сервер должны взаимодействовать через запросы и ответы, 
передавая **представления ресурсов**. REST не является стандартом или протоколом — это набор архитектурных ограничений 
и принципов.

**2. Что такое RESTful и принцип RESTful приложений?**
**RESTful** — это приложение или сервис, который реализует архитектуру REST и следует её ограничениям. Ключевые принципы RESTful-приложений:

- **Унифицированный интерфейс (Uniform Interface)** — все ресурсы идентифицируются через URI (например, `/users/123`), а действия выполняются стандартными HTTP-методами (GET, POST, PUT, DELETE).
- **Отсутствие состояния (Stateless)** — каждый запрос от клиента содержит всю информацию, необходимую серверу для его обработки. Сервер не хранит состояние сессии клиента между запросами.
- **Кэшируемость** — ответы сервера могут быть помечены как кэшируемые или не кэшируемые.
- **Клиент-серверная архитектура** — чёткое разделение ответственности между клиентом (интерфейс) и сервером (данные и логика).

**3. Что такое web-система?**
Web-система — это программная система, доступ к которой осуществляется через веб-браузер или другой HTTP-клиент по сети. Она обычно состоит из клиентской части (frontend), серверной части (backend) и базы данных. В контексте лабораторной работы web-система — это совокупность трёх серверов `TDWA04-01` и API-шлюза `Ocelot`, которые совместно обрабатывают запросы.

### 🚪 API Gateway

**4. Что такое API Gateway?**
API Gateway — это **сервер или сервис**, который находится между клиентами и набором внутренних (backend) сервисов. Он действует как **единая точка входа** для всех клиентских запросов и выполняет роль обратного прокси (reverse proxy), маршрутизируя каждый запрос к соответствующему внутреннему сервису.

**5. Для чего используется API Gateway?**
- **Централизованная маршрутизация** — направление запросов к нужным сервисам на основе пути, метода или других правил.
- **Инкапсуляция внутренней архитектуры** — клиент не знает, сколько сервисов за шлюзом и как они называются.
- **Централизация сквозных задач** — на шлюзе можно единообразно настроить аутентификацию, логирование, ограничение скорости (rate limiting), кэширование и мониторинг для всех сервисов.

**6. Преимущества использования API Gateway:**
- **Единая точка входа** для клиентов — упрощает клиентский код и снижает связанность.
- **Снижение дублирования** — общие политики (аутентификация, CORS, лимиты) настраиваются один раз на шлюзе, а не в каждом сервисе.
- **Стабильный интерфейс** — внутренние сервисы можно менять, объединять или переносить без изменения публичного API.
- **Повышенная безопасность** — шлюз скрывает внутреннюю топологию и может фильтровать нежелательный трафик.

### 🧩 Паттерн BFF и реализации

**7. Что такое паттерн Backend for Frontend (BFF)?**
BFF — это паттерн проектирования, при котором для **каждого типа клиента** (например, веб-приложение, 
мобильное приложение) создаётся **отдельный backend-сервис** (BFF-слой). Этот слой находится между фронтендом и 
основными backend-сервисами и адаптирует их ответы под конкретные потребности данного клиента. Вместо одного 
универсального API для всех клиентов каждый клиент получает свой «фасад», который возвращает именно те данные и в том 
формате, которые нужны этому клиенту.

**8. Какие есть известные реализации API Gateway?**
- **Ocelot** — библиотека для .NET, легковесный шлюз, встраиваемый в ASP.NET Core приложение.
- **NGINX** — высокопроизводительный веб-сервер и обратный прокси, который также может выполнять функции API Gateway.
- **Kong** — популярный шлюз на основе NGINX с богатой экосистемой плагинов.
- **Traefik** — современный обратный прокси и шлюз, ориентированный на микросервисы и контейнеры.
- **Amazon API Gateway** — полностью управляемый сервис от AWS.
- **Azure API Management** — облачный сервис от Microsoft.
- **Spring Cloud Gateway** — шлюз для экосистемы Spring (Java).
- **Apache APISIX** — высокопроизводительный облачный шлюз.

### 🐈 Ocelot

**9. Что такое Ocelot?**
Ocelot — это **легковесная библиотека с открытым исходным кодом** для платформы .NET, которая превращает обычное ASP.NET Core приложение в **API Gateway**. Она не является отдельным сервером (как NGINX), а подключается как NuGet-пакет и настраивается через JSON-файл.

**10. Отличие NGINX и Ocelot:**
| Критерий | NGINX | Ocelot |
|---|---|---|
| **Технологическая база** | Написан на C, это самостоятельный веб-сервер и обратный прокси | Библиотека для .NET (C#), работающая внутри вашего приложения |
| **Назначение** | Универсальный высокопроизводительный сервер для отдачи статики, балансировки, проксирования | Специализированный API-шлюз для микросервисной архитектуры на .NET |
| **Производительность** | Очень высокая, оптимизирован для больших нагрузок | Хорошая, но обычно уступает NGINX в «сырой» производительности |
| **Гибкость настройки** | Сложные конфигурационные файлы, но очень мощные | Простой JSON-конфиг, ориентированный на маршрутизацию API |
| **Интеграция** | Не зависит от языка backend | «Родной» для .NET-стека, легко интегрируется с ASP.NET Core |

**11. Для чего используется Ocelot?**
Ocelot используется для создания **API Gateway в микросервисных архитектурах на .NET**. Он принимает входящие 
HTTP-запросы, применяет к ним правила (маршрутизация, аутентификация, ограничение скорости, Circuit Breaker) и 
перенаправляет их в соответствующие внутренние сервисы. Также Ocelot умеет агрегировать ответы от нескольких 
сервисов, кэшировать их и обеспечивать отказоустойчивость.

**12. Что такое Circuit Breaker (Предохранитель) в Ocelot и зачем он нужен?**
Circuit Breaker — это механизм **защиты от каскадных отказов**. Если внутренний сервис начинает отвечать ошибками или 
слишком медленно, «предохранитель» **размыкает цепь**: Ocelot перестаёт отправлять запросы к этому проблемному 
сервису на заданное время и сразу возвращает клиенту ошибку (или закэшированный ответ). Это предотвращает 
перегрузку уже упавшего сервиса и позволяет системе быстрее восстановиться. В Ocelot Circuit Breaker 
настраивается на уровне каждого маршрута через `QoSOptions` (Quality of Service) и может работать как 
через встроенный механизм, так и через библиотеку Polly.

**13. Как Ocelot понимает, на какой именно сервер отправить какой запрос?**
Ocelot анализирует **входящий запрос (Upstream)** и сопоставляет его с правилами, описанными в конфигурационном 
файле `ocelot.json`. Для каждого маршрута заданы два ключевых параметра:

- **`UpstreamPathTemplate`** — шаблон пути, по которому приходит запрос (например, `/api`).
- **`UpstreamHttpMethod`** — HTTP-метод, на который реагирует данное правило (например, `GET`).

Когда запрос поступает, Ocelot ищет в массиве `Routes` правило, у которого совпадают и путь, и метод. Найдя совпадение, 
он берёт из этого же правила параметры **`DownstreamPathTemplate`**, **`DownstreamHostAndPorts`** и 
**`DownstreamScheme`**, чтобы сформировать новый URL и отправить запрос уже на конкретный внутренний сервис. 
Если совпадений нет, возвращается ошибка (обычно 404).

В вашей лабораторной работе это выглядит так: запрос `GET /api` совпадает с правилом, где `UpstreamHttpMethod` равен `GET`, а `DownstreamHostAndPorts` указывает на `localhost:5001` — значит, запрос уходит на сервер X.

**14. Как настраивается файл Ocelot?**
Конфигурация Ocelot хранится в **JSON-файле** (обычно `ocelot.json`). В нём есть два основных раздела:

- **`Routes`** — массив маршрутов. Каждый маршрут описывает правило: какой входящий путь и метод (`UpstreamPathTemplate`, `UpstreamHttpMethod`) должен быть перенаправлен на какой внутренний адрес (`DownstreamPathTemplate`, `DownstreamScheme`, `DownstreamHostAndPorts`).
- **`GlobalConfiguration`** — глобальные настройки шлюза, например его собственный базовый адрес (`BaseUrl`).

Файл подключается в коде приложения (`Program.cs`) через `builder.Configuration.AddJsonFile("ocelot.json", ...)`, после чего Ocelot использует его для маршрутизации. При необходимости конфигурацию можно разбивать на несколько файлов и объединять их, а также использовать переменные окружения.
